# رِواق — متجر iOS عربي

واجهة عربية متجاوبة، بحث وأقسام وتفاصيل وإصدارات، مع تجميع مصادر AltStore / GithubStore وجلب أحدث إصدارات GitHub المصرح بها. مستند إلى أجزاء معدّلة من webipagui وGithubStore بترخيص MIT؛ التفاصيل في [إشعارات المصادر](THIRD_PARTY_NOTICES.md).

## ابدأ من هنا

المتجر يبدأ فارغًا عمدًا. زر «استعراض نموذج المتجر» يعرض تطبيقات وهمية بلا تنزيل، ولا تدخل هذه الأمثلة في المصدر الموحّد. لم تُضف تطبيقات مدفوعة أو معدلة أو مصادر غير مأذونة.

1. افتح المتجر ثم «إعداد المتجر».
2. أضف مصدر AltStore (أو رابط `source.json` من خادم GithubStore قائم)، أو مستودع GitHub عامًا ينشر IPA في Releases.
3. لكل تطبيق، أدخل معرّفه الحقيقي والقسم ونطاقات التنزيل المسموحة ورابط إذن التوزيع ووصفه. لا يكفي أن يكون مستودعه عامًا.
4. لمصدر GitHub، أدخل نمط اسم الملف مثل `MyApp-*.ipa`؛ يجب أن يطابق ملفًا واحدًا. جلب أحدث إصدار مستقر فقط مقصود؛ لا نخمن معرّف التطبيق من اسم المستودع.
5. اضغط «إضافة إلى ملف الإعداد»، وكرر للتطبيقات الأخرى. إدخالات المصدر نفسه تُجمع. للتعديل على ملف سابق، استورده أولًا.
6. نزّل `sources.json` وارفعه إلى مجلد `config` في GitHub بدل الملف الموجود، ثم احفظ التغيير. معالج الإعداد ينشئ ملفًا محليًا ولا يغيّر المتجر عن بعد.

**لا تكتب مفاتيح أو أسرارًا أو نصوص أذونات خاصة في الملف العام.** استخدم مرجع إذن قابلًا للنشر. المسودة مؤقتة ولا تبقى بعد إعادة تحميل الصفحة.

## النشر على GitHub Pages — مرة واحدة

1. من المستودع، افتح **Settings → Pages → Build and deployment → Source → GitHub Actions**.
2. افتح **Actions → Update catalog and publish → Run workflow**.
3. بعد نجاح التشغيل، افتح رابط الموقع الظاهر في صفحة Pages أو نتيجة deployment.
4. يعمل التحديث عند حفظ تعديل إلى `main`، أو يدويًا، وكل ست ساعات تقريبًا. جدولة GitHub قد تتأخر، وقد تتوقف للمستودعات العامة غير النشطة حسب سياسة GitHub؛ راقب سجل Actions.

الرابط المتوقع لهذا المستودع: `https://aliammarsss3-collab.github.io/riwaq-ios-store/`، لكنه لا يصبح متاحًا حتى نجاح النشر. يدعم المشروع مسارًا فرعيًا؛ روابط التفاصيل مثل `#app/com.example.app` لا تحتاج إعداد إعادة توجيه للخادم.

## التشغيل على الحاسوب

ثبت Node.js 22 أو أحدث من [الموقع الرسمي](https://nodejs.org/). نزّل المستودع من **Code → Download ZIP** وفك الضغط، ثم افتح الطرفية داخل المجلد:

```sh
npm run sync
npm start
```

افتح `http://127.0.0.1:4173`. للإيقاف اضغط Ctrl+C. لا تحتاج `npm install` أو Docker؛ لا توجد حزم خارجية. لا تفتح HTML مباشرة لأن تحميل البيانات يحتاج خادم HTTP.

```sh
npm test
npm run build
```

الناتج الثابت في `dist/`. لرفعه إلى استضافة ثابتة أخرى، شغّل المزامنة والبناء أولًا وارفع محتويات هذا المجلد فقط. لا يوجد خادم إدارة عام أو قاعدة بيانات. التعديل في GitHub هو مسار الإدارة المحمي بحسابك.

## مثال إعداد (غير مفعّل)

استبدل جميع القيم ببيانات تطبيقك، ولا تعتمد المثال كإذن توزيع:

```json
{
  "name": "رِواق",
  "identifier": "com.riwaq.store",
  "sources": [{
    "id": "my-apps",
    "name": "تطبيقاتي",
    "type": "github",
    "url": "https://github.com/OWNER/REPOSITORY",
    "apps": [{
      "name": "تطبيقي",
      "bundleIdentifier": "com.example.myapp",
      "category": "أدوات",
      "assetPattern": "MyApp-*.ipa",
      "downloadHosts": ["github.com"],
      "rightsConfirmed": true,
      "permissionURL": "https://example.com/distribution-permission",
      "permissionNote": "أملك حقوق هذا التطبيق وأسمح بتوزيع هذه النسخ"
    }]
  }]
}
```

لمصدر AltStore أو GithubStore، استخدم `type: "altstore"` ورابط JSON عامًا عبر HTTPS. يجب إدراج كل bundleIdentifier المسموح به؛ التطبيقات الأخرى تُستبعد تلقائيًا. نطاقات التنزيل مطابقة تمامًا بلا wildcards؛ أضف نطاق CDN الفعلي إذا لزم. المستودعات الخاصة وروابط التنزيل المحمية أو المؤقتة ليست مدعومة.

## كيف تعمل التحديثات؟

- يتصل سكربت المزامنة بالمصادر وقت البناء، فلا تعتمد الواجهة على CORS الخاص بكل مصدر.
- يجمع نسخ التطبيق حسب معرّفه، يزيل التكرار، ويرتبها بالتاريخ ثم رقم الإصدار. يُعرض مصدر كل نسخة ومرجع إذنها.
- مصادر AltStore تحتفظ بالإصدارات التي يقدمها المصدر؛ تكامل GitHub يعرض أحدث إصدار مستقر فقط ولا يؤرشف الإصدارات القديمة.
- تُنشر بيانات العرض في `data/catalog.json` والمصدر الموحّد في `data/source.json`. تصدير AltStore يحتاج اختبارًا على أداة التثبيت التي تستخدمها؛ بعض الأدوات تتطلب بيانات إضافية مثل الصلاحيات أو bundle IDs الفرعية، لا يستخرجها المشروع من IPA.
- فشل مصدر واحد لا يوقف غيره: تظهر رسالة الخطأ ويُحذف محتواه من هذه الدفعة بدل عرض بيانات قديمة على أنها حديثة. إزالة تطبيق من قائمة السماح تزيله عند النشر التالي.
- لا تُنزّل ملفات IPA إلى الخادم أو المستودع. روابط التنزيل تشير إلى الناشر. بيانات المصدر نص عادي ولا يُنفّذ HTML الوارد فيها.

## حدود الأمان والتشغيل

جلب بيانات المصادر يقبل HTTPS فقط، يفحص DNS ويثبت عنوان الاتصال العام لتقليل SSRF وDNS rebinding، ويرفض الشبكات الخاصة والتحويلات غير الآمنة. حد الملف 5MB والمهلة 20 ثانية لكل طلب، و3 تحويلات كحد أقصى. الاتصال الخارجي IPv4 فقط؛ مصدر يعمل على IPv6 وحده لن يعمل. توكن Actions يرسل إلى `api.github.com` فقط ولا يُدرج في الواجهة أو الملفات. راجع تغيير الشيفرة وسير العمل قبل دمجه؛ مالك المستودع يتحكم بالنشر.

قائمة السماح تضبط الروابط الأولية؛ نطاق الناشر قد يعيد توجيه تنزيل الملف إلى CDN. الثقة بالناشر والتحقق من محتوى التطبيق والتراخيص مسؤولية مراجعة بشرية. لا يتضمن المشروع فحص برمجيات ضارة أو تحققًا تشفيريًا من IPA أو توقيعًا أو تثبيتًا مباشرًا.

## حل المشكلات

| الحالة | الإجراء |
| --- | --- |
| المتجر فارغ | أضف تطبيقات إلى `config/sources.json` ثم راجع Actions والمصادر. |
| HTTP 403 / 429 | قد يكون حد GitHub أو المصدر؛ انتظر أو راجع صلاحية الوصول. توكن Actions المدمج مستخدم تلقائيًا. |
| نمط IPA لا يطابق ملفًا واحدًا | راجع أسماء Assets في أحدث Release وحدد النمط بدقة. |
| خطأ إذن أو معرّف | أكمل حقول الإذن ومعرّف التطبيق الحقيقي، ولا تستخدم تأكيدًا غير صحيح. |
| النشر يفشل | تأكد أن Pages مضبوط على GitHub Actions وأن Actions مسموح في المستودع. |
| لا يُثبّت التطبيق بالضغط | التنزيل وحده لا يثبت IPA؛ استخدم أداة توقيع/تثبيت متوافقة حسب تعليماتها. |

## الملفات المهمة

`config/sources.json` للإعداد، `lib/catalog.mjs` للتطبيع، `scripts/sync.mjs` للجلب، `public/` للواجهة، `test/` للاختبارات، `.github/workflows/` للفحص والنشر. نسخة `public/catalog.mjs` تُحدّث تلقائيًا عند البناء والتشغيل من الملف الأصلي.
